# SEO Phase 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete SEO Phase 2 expansion items that are actionable via code changes.

**Architecture:** Three independent tasks: ContactPage schema on /dove-siamo, meta description audit on /market, and commit+push of updated SEO docs. Each task touches separate files with no cross-dependencies.

**Tech Stack:** TypeScript, React, TanStack Start, Schema.org JSON-LD

**Spec:** docs/seo/IMPLEMENTATION-ROADMAP.md (Phase 2), docs/seo/SITE-STRUCTURE.md

## Global Constraints

- Animations are sacred: do not modify GSAP, Lenis, ScrollTrigger, Framer Motion, CSS transitions/animations, or scroll-driven effects.
- Runtime: Cloudflare Workers (no Node-only APIs in server code).
- Data source: all business data lives in `src/data/masseria.ts`. Never hardcode contacts/hours/coordinates elsewhere.
- Commits: conventional format (`feat:`, `fix:`, `chore:`, `refactor:`). End with `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.
- ASCII-only in public text files (robots.txt, sitemap.xml) to avoid encoding issues on validator tools.

## Review Focus

1. ContactPage schema must reference the same geo coordinates as `MASSERIA` in `src/data/masseria.ts` — a hardcoded mismatch breaks local pack eligibility.
2. Meta description length must stay under 160 chars to avoid SERP truncation.
3. JSON-LD must be valid JSON when serialized — a trailing comma or unescaped quote breaks rich results silently.
4. Build must pass after every change — Cloudflare Pages deploys automatically on push to main.
5. No animation or style files touched — only route-level head() and component markup.
